# per-proc-route

Инструмент для маршрутизации IPv4-трафика выбранных приложений в обход основного
TUN-интерфейса. Например, если прокси-клиент направляет трафик через TUN, с
помощью `per-proc-route` можно отправить трафик отдельных приложений через
обычный шлюз.

## Как это работает

`ppr start` создаёт отдельный маршрут и правило маршрутизации, загружает
eBPF-программы и закрепляет их карты и ссылки в `/sys/fs/bpf`.

Программа на `sys_enter_execve` сравнивает путь, переданный в `execve()`, со
списком приложений. При совпадении она добавляет TGID процесса в карту
`policy_map`. Запись наследуется дочерними процессами и удаляется после
завершения группы процессов. Программа, прикреплённая к корневой cgroup,
помечает IPv4-сокеты таких процессов. Для этой метки правило маршрутизации
выбирает отдельную таблицу со шлюзом из конфигурации.

`ppr update` заменяет список путей в закреплённой eBPF-карте. Изменение
применяется к следующим вызовам `execve()`: уже запущенные процессы не
добавляются и не удаляются из `policy_map` при обновлении списка.

## Требования

- Linux с BTF ядра в `/sys/kernel/btf/vmlinux`, смонтированными bpffs в
  `/sys/fs/bpf` и cgroup v2 в `/sys/fs/cgroup`.
- Права на изменение маршрутов, загрузку eBPF и создание pin-файлов. Проще
  всего запускать `ppr` от имени root.
- Для сборки из исходников: Go версии, указанной в `go.mod`, `bpftool`, Clang,
  LLVM и заголовки libbpf.

## Сборка

Склонируйте репозиторий и выполните команды на **машине сборки**:

```bash
git clone https://github.com/lb2114/per-proc-route.git
cd per-proc-route
bpftool btf dump file /sys/kernel/btf/vmlinux format c > internal/ebpf/vmlinux.h
go generate ./internal/ebpf
mkdir -p bin
go build -o bin/ppr ./ppr
```

`vmlinux.h` нужен компилятору для типов ядра. `bpf2go` встраивает собранный
eBPF-объект в Go-программу. При запуске на другой машине загрузчик использует
BTF её ядра для CO-RE-релокаций: повторять дамп и компиляцию там не требуется.
Исходный `vmlinux.h` и сгенерированные файлы сейчас не хранятся в репозитории,
поэтому при сборке из клона шаги с `bpftool` и `go generate` обязательны.
Работа готового бинарника зависит от поддержки используемых eBPF-хуков целевым
ядром.

## Использование

Создайте файл `config` с адресом обычного шлюза и именем интерфейса, через
который доступен этот шлюз. Каждое значение — на отдельной строке:

```text
192.168.0.1
wlan0
```

Создайте файл `procs` с абсолютными путями к исполняемым файлам, по одному на
строку:

```text
/usr/bin/steam
/usr/bin/chromium
```

Путь должен совпадать с аргументом `execve()`. Относительные пути не
поддерживаются; длина одного пути — не более 255 байт, количество записей — не
более 1024.

Настройте маршрутизацию и загрузите eBPF-программы:

```bash
sudo bin/ppr start procs config
```

В случае изменения файла `procs` обновите список без повторной загрузки программ:

```bash
sudo bin/ppr update procs
```

Чтобы снять закрепление eBPF-ссылок и карт, выполните:

```bash
sudo bin/ppr stop
```

`stop` не удаляет маршрут и правило маршрутизации, созданные командой `start`.
Повторный вызов `stop` успешен, даже если pin-файлов уже нет.

Справка по командам:

```bash
bin/ppr help
```

Программа завершает работу после `start`: закреплённые ссылки продолжают
удерживать eBPF-программы в ядре. Для изменения списка используйте `update`,
для удаления pin-файлов — `stop`.

## Текущие параметры

- Таблица маршрутизации: `2114`.
- Метка сокета: `0x55`.
- Крепление программы маркировки: корневая cgroup `/sys/fs/cgroup`.
- Pin-файлы карт и ссылок: `/sys/fs/bpf/ppr_*`.
- Маркируются только IPv4-сокеты; IPv6 пока не поддерживается.

Часть значений задана в `internal/config/config.go` и `internal/ebpf/marker.c`
и меняется перед сборкой.
