# per-proc-route

Инструмент для маршрутизации трафика отдельных приложений в обход основного
TUN-интерфейса, привязанного к прокси-клиенту в системе.

## Описание

Представим, что на устройстве установлен клиент Xray. Он слушает TUN-интерфейс
`tun0` и весь трафик, пришедший с него, отправляет на удаленный прокси-сервер.
Xray позволяет гибко настраивать правила маршрутизации, но его функционал
не предоставляет возможности создавать правила, которые применяются к трафику
конкретных процессов.

Именно для решения этой задачи и был создан `per-proc-route`. С его помощью
можно направить весь трафик выбранного приложения в обход интерфейса `tun0` и,
как следствие, в обход прокси-клиента Xray.

## Установка
Клонируем репозиторий
```bash
git clone git@github.com:lb2114/per-proc-route.git
cd per-proc-route
```
Перед сборкой необходимо сделать дамп заголовков ядра и поместить их в internal/ebpf
```bash
bpftool btf dump file /sys/kernel/btf/vmlinux format c > internal/ebpf/vmlinux.h
```
```bash
go generate
```
```bash
mkdir bin
go build ./...
```
После сборки получаем два исполняемых файла:
```bash
- `ppr` - CLI-клиент.
- `pprd` - демон, который должен запускаться от имени `root`.
```
## Использование

Сначала нужно создать группу `ppr` и добавить туда пользователя, который будет
использовать CLI-клиент:

```bash
sudo groupadd ppr
sudo usermod -aG ppr "$USER"
```

После добавления пользователя в группу нужно перелогиниться или открыть новую
пользовательскую сессию, чтобы изменения вступили в силу.

Для ручного запуска демона:

```bash
sudo bin/pprd
```

После этого приложение можно запустить через CLI-клиент:

```bash
bin/ppr run <cmd> [arguments]
```

Например:

```bash
bin/ppr run curl https://example.com
```

## Создание systemd-unit

Можно создать systemd unit, чтобы демон запускался автоматически.

Копируем демон в директорию, в которой лежат исполняемые файлы, доступные через PATH
```bash
sudo cp bin/pprd /usr/local/bin/pprd
```

Затем создаем systemd-unit
```Bash
sudo nano /etc/systemd/system/pprd.service
```
```ini
[Unit]
Description=per-proc-route daemon

[Service]
Type=simple
ExecStart=/usr/local/bin/pprd
Restart=on-failure
RestartSec=2s

[Install]
WantedBy=multi-user.target
```

Запустите сервис:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pprd.service
```

## Как это работает

Процессы, трафик которых нужно пустить в обход основного TUN-интерфейса,
добавляются в cgroup `ppr/direct`. В eBPF загружается программа типа
`BPF_CGROUP_INET_SOCK_CREATE` с хуком на создание сокета процессами из этой
cgroup.

Сама eBPF-программа присваивает сокету метку и, как следствие, всем его пакетам. Для метки создаются правила маршрутизации, которые перенаправляют
весь помеченный трафик в отдельную таблицу маршрутизации со стандартным шлюзом
вместо TUN-интерфейса прокси-клиента.

## Текущие настройки

Основные параметры заданы в `internal/config/config.go` и настраиваются до компиляции:

- шлюз: `192.168.0.1`
- таблица маршрутизации: `2114`
- сетевой интерфейс: `wlan0`
- mark: `0x55`
- cgroup: `/sys/fs/cgroup/ppr/direct`
- путь к UNIX-сокету демона: `/run/ppr/`
- имя UNIX-сокета демона: `pprd.sock`
- группа, которой разрешено подключаться к сокету: `ppr`

Перед использованием стоит проверить эти значения и при необходимости заменить
их под свою систему.

## Замечания

- Проект ориентирован на Linux и использует eBPF/cgroup, поэтому для запуска
  демона нужны соответствующие права.
- Если основной интерфейс, шлюз или mark отличаются от значений по умолчанию,
  их нужно изменить перед сборкой.
