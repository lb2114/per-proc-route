# per-proc-route

Инструмент для маршрутизации трафика отдельных приложений в обход основного
TUN-интерфейса, привязанного к прокси-клиенту в системе.

## Описание

Представим, что на устройстве установлен клиент Xray. Он слушает TUN-интерфейс
`tun0` и весь трафик, пришедший с него, отправляет на удаленный прокси-сервер.
Xray позволяет гибко настраивать правила маршрутизации, но его функционал
не предоставляет возможности создавать правила, которые применяются к трафику
конкретных процессов.

Именно для решения этой задачи и был создан `per-proc-route`. С его помощью
можно направить весь трафик выбранного приложения в обход интерфейса `tun0` и,
как следствие, в обход прокси-клиента Xray.

## Установка

Клонируйте репозиторий

```bash
git clone git@github.com:lb2114/per-proc-route.git
cd per-proc-route
```

Перед сборкой сделайте дамп заголовков ядра и поместите его в `internal/ebpf`

```bash
bpftool btf dump file /sys/kernel/btf/vmlinux format c > internal/ebpf/vmlinux.h
```

Сгенерируйте eBPF-обвязку

```bash
go generate ./...
```

Соберите исполняемые файлы

```bash
mkdir -p bin
go build -o bin/ppr ./ppr
go build -o bin/pprd ./pprd
```

После сборки будут доступны два исполняемых файла:

- `ppr` - CLI-клиент.
- `pprd` - демон, который должен запускаться от имени `root`.

При необходимости создайте конфигурационный файл для путей к программам,
которые нужно пустить в обход основного интерфейса

```bash
nano bin/config.conf
```

## Использование

Сначала создайте группу `ppr` и добавьте в нее пользователя, который будет
использовать CLI-клиент

```bash
sudo groupadd ppr
sudo usermod -aG ppr "$USER"
```

После добавления пользователя в группу перелогиньтесь или откройте новую
пользовательскую сессию, чтобы изменения вступили в силу.

Доступны два варианта использования:

- добавление путей к программам в конфигурационный файл;
- использование CLI-клиента.

В первом варианте абсолютные пути к исполняемым файлам добавляются в
`config.conf` по одному на строку

```txt
# config.conf
/usr/bin/steam
/usr/bin/chromium
...
```

После этого запустите демон с путем к конфигурационному файлу

```bash
sudo bin/pprd --config <путь_к_конфигурационному_файлу>
```

Для запуска через CLI сначала запустите демон. Конфигурационный файл может быть
пустым

```bash
sudo bin/pprd --config <путь_к_конфигурационному_файлу>
```

После этого запустите нужное приложение через CLI-клиент

```bash
bin/ppr run <cmd> [arguments]
```

Например

```bash
bin/ppr run curl https://example.com
```

## Создание systemd-юнита

Создайте `systemd`-юнит, чтобы демон запускался автоматически.

Скопируйте `pprd` в системный каталог

```bash
sudo cp bin/pprd /usr/local/bin/pprd
```

Создайте каталог для конфигурационного файла

```bash
sudo mkdir -p /etc/pprd/
```

Создайте конфигурационный файл

```bash
sudo nano /etc/pprd/config.conf
```

Создайте файл `systemd`-юнита

```bash
sudo nano /etc/systemd/system/pprd.service
```

Укажите путь к конфигурационному файлу в поле `ExecStart`

```ini
[Unit]
Description=per-process-route daemon
After=network.target

[Service]
ExecStart=/usr/local/bin/pprd --config /etc/pprd/config.conf
Type=simple
Restart=on-failure
RestartSec=2s

[Install]
WantedBy=multi-user.target
```

Перечитайте конфигурацию `systemd` и запустите сервис

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now pprd.service
```

## Как это работает

Процессы, трафик которых нужно пустить в обход основного TUN-интерфейса,
добавляются в cgroup `ppr/direct`.

При запуске демон читает конфигурационный файл и загружает указанные абсолютные
пути в eBPF map.

В eBPF загружаются две программы.

Первая программа имеет хук на tracepoint `sys_enter_execve`. Один из аргументов
системного вызова `execve()` - путь к исполняемому файлу. Внутри eBPF-программы
этот путь сверяется с путями, загруженными в eBPF map. Если путь совпадает, PID
процесса отправляется в user-space часть, которая добавляет процесс в cgroup.

Вторая программа имеет хук на создание сокета процессами из этой же cgroup. Она
присваивает сокету метку, для которой создаются правила маршрутизации. Эти
правила перенаправляют весь помеченный трафик в отдельную таблицу со
стандартным шлюзом вместо TUN-интерфейса прокси-клиента.

## Текущие настройки

Основные параметры заданы в `internal/config/config.go` и настраиваются до
компиляции:

- шлюз: `192.168.0.1`
- таблица маршрутизации: `2114`
- сетевой интерфейс: `wlan0`
- mark: `0x55`
- cgroup: `/sys/fs/cgroup/ppr/direct`
- путь к UNIX-сокету демона: `/run/ppr/`
- имя UNIX-сокета демона: `pprd.sock`
- группа, которой разрешено подключаться к сокету: `ppr`

Перед использованием стоит проверить эти значения и при необходимости заменить
их под свою систему.

## Замечания

- Проект ориентирован на Linux и использует eBPF/cgroup, поэтому для запуска
  демона нужны соответствующие права.
- Если основной интерфейс, шлюз или mark отличаются от значений по умолчанию,
  их нужно изменить перед сборкой.
